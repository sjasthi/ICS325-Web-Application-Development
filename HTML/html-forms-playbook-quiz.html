📝 HTML Forms — Playbook

Code for Good · Week 3 · Forms, validation basics & structured prompt templates

🧭 What is an HTML form?

A form is how a web page listens. Sign-ups, searches, donations, volunteer registrations and even AI prompt builders are all forms. The form collects what people type and packages it up to send to a server — the first step in every full-stack app you will build this year.

📥 Collect input

Text boxes, dropdowns, checkboxes and buttons all live inside a <form> tag.

🏷️ name = value

When the form is sent, each input becomes a name=value pair. No name, no data.

🛡️ Check twice

The browser checks the data first (validation). The server must always check it again, because browser checks can be switched off.

🚫 Placeholder ≠ label

A placeholder disappears as soon as someone types. Always keep a real <label>.

📱 Pick the right type

type="email" checks for an @ sign and shows the @ key on phones. type="number" shows a number pad.

🔘 Radio

Exactly one answer from a short list (2–5 options).

☑️ Checkbox

🌐 Client-side (browser)

Fast and friendly: helps people fix mistakes instantly. But anyone can turn it off with novalidate or developer tools.

🖥️ Server-side

The real guard. Your PHP code (later this year) must check every value again before saving it.

🧪 Test like a hacker

Try empty fields, huge numbers, emoji and spaces. If your form accepts nonsense, tighten the rules.

📮 Sending the Data

When a form is submitted, the browser gathers every input that has a name and sends the pairs to the action URL using the method you chose.

GET vs POST

Three kinds of buttons

🎯 action

The URL that receives the data, such as /join.php. Leave it out and the form sends to the same page.

🔍 GET

Good for searches and filters: the result page can be bookmarked and shared. Never for passwords.

🔒 POST

Good for logins, sign-ups and anything that changes data or is private.

🤖 Structured Prompt Templates

A structured prompt template is a fill-in-the-blanks recipe for asking an AI tool like Claude. Instead of one vague line, you fill in the same five parts every time. Sound familiar? That is exactly what a form does!

🎭 Role

Who should the AI act as? "Act as a patient coding tutor."

🎯 Task

What exactly do you want? "Explain GET vs POST."

📚 Context

Background it needs. "I'm in 8th grade and just learned forms."

📋 Format

How the answer should look. "A bulleted list with one example."

📏 Constraints

Limits and rules. "Under 150 words. No jargon."

😐 Vague prompt

explain forms

🤩 Structured prompt

Act as a patient coding tutor. Task: explain how HTML form validation works. Context: I'm in 8th grade and know basic HTML tags. Format: 4 bullet points plus one code example. Constraints: under 150 words.
